Project overview

What we're building

A structured pruning + activation healing pipeline (TIM-MGDT) that identifies which transformer layers are elastic vs critical, prunes the elastic ones, and heals the activation drift — recovering perplexity while cutting parameters, latency, and memory by ~50%.

Why this matters

Existing pruning methods either destroy quality or require expensive retraining. We discovered that Layer 10 in GPT-2 is elastic, not broken — the +108% PPL explosion on hard removal shows over-weighting, not architectural damage. A 2% scaling fix restores balance. TIM-MGDT exploits this insight systematically.

Where we are today

Phase 15 complete. We have moved beyond theoretical pruning into True Hardware Compression (Layer Dropping). By dropping 4 contiguous layers, we achieve a guaranteed 15.5% latency reduction. We then utilize our novel Boundary-Focused Surgical LoRA to heal the resulting activation discontinuities, dramatically outperforming global healing strategies.

The research question

Can exhaustive causal sensitivity metrics (ΔCE) reliably identify and exploit layer-level elasticity to achieve lossless (< 5% PPL) structured compression at 50%+ parameter reduction without retraining?

Phase 15 Oracle-Guided Layer Dropping & Boundary Healing

Unlike parameter masking (which leaves memory fragmentation), Layer Dropping completely removes a contiguous block of layers, achieving true hardware compression. We identify the 4-layer block with the lowest causal sensitivity and drop it, reducing depth by 12.5% and yielding a guaranteed ~15.5% reduction in inference latency.

The Healing Insight: Dropping contiguous layers creates a sharp, localized discontinuity in the activation flow. We demonstrate that our Boundary-Focused Surgical LoRA (which targets only the layers immediately adjacent to the "incision") dramatically outperforms standard global healing methods, recovering perplexity while retaining the full speedup.

Key decisions
TopicDecisionRationale
ActionabilityOracle Compute Cost is fast We proved that calculating the exhaustive ΔCE Bathtub Curve for a 7B model takes under 4 minutes. It is highly actionable.
Layer DroppingContiguous Block Drop Instead of dropping scattered layers which causes memory fragmentation, we drop the contiguous 4-layer block with the lowest causal sensitivity to guarantee real-world 15.5% latency reductions.
Healing StrategyBoundary-Focused Healing Layer dropping creates a sharp, localized discontinuity in the activation flow. Healing just the incision boundaries (layers immediately before/after the drop) dramatically outperforms healing globally sensitive layers.
Recovery InitializationRandom Init > SVD Init SVD forces dense noise into sparse structures, polluting undamaged weights. Random Init allows the optimizer to find a new sparse-compatible manifold.
MetricC4 Held-Out Perplexity To preempt data contamination claims (Wikitext-2), we use C4 evaluation exclusively.
